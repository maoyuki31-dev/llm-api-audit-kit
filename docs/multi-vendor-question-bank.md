# 四、测评方法学（必读）


目标：让跨云厂对比结论可复现、可归因、防作弊。以下规则与“一、使用规范”配合使用。


**1. 多次采样（稳定性）**：每题在固定参数下重复调用 3–5 次并记录每次输出；判定“稳定”需多次结果一致，不以单次输出下结论。

**2. 盲评（防名字偏见）**：输出先脱敏（去掉模型名/厂商名），评分人只按 评分标准 打分，评完再揭晓厂商。

**3. 错题归因**：对每题错误做分类标记：幻觉 / 推理断裂 / 格式违规 / 拒答不当 / 指令未遵循，统计错误类型分布，比单一总分更有诊断价值。

**4. 防过拟合**：题库固定是基线。

**5. 评分落地**：客观题（单选、计算、JSON 输出）按标准答案自动判分；开放式题按 0/1/2 分 rubric 人工或模型盲评打分。

# 五、评分执行方案（落地细则）


本方案解决“自动判分怎么执行”：客观题脚本判分、开放式题 LLM 盲评、结果统一登记汇总。与“四、测评方法学”配合使用。


## 1. 客观题自动判分（脚本比对）

适用题：单选、计算、JSON 输出、数字保真等有唯一答案的题（如 C7、D7、E8、G1、G7、H4）。

1. 数值题：解析模型输出中的数字与标准答案比对，允许 ±1% 容差（百分比题允许 ±0.5 个百分点）。
2. JSON 题：用 JSON 解析器校验结构合法性与键名一致性，再比对关键字段值。
3. 格式/保真题：用正则或精确匹配检查（是否输出表格符号、中文大写金额是否正确等）。
4. 得分映射：完全命中=2；部分命中（如单位错、少一个值）=1；不匹配或编造=0。

## 2. 开放式题盲评（LLM 按 评分标准打分）

适用题：总结、方案、判断说明类（如 C3、D4、G4、H2）。

评分提示词模板：

```text
你是一个客观的评分员，请按以下标准给模型回答打分（0/1/2）：
【题目】...
【标准答案要点】...
【评分细则】2分=...；1分=...；0分=...
【模型回答（已脱敏）】...
请只输出：得分（0/1/2）+ 一句评分理由。
```

注意事项：评分前去除模型名与厂商名；同一题的所有厂商用同一评分会话；每题取多次采样分数的平均值。

## 3. 结果登记与加权汇总

登记表建议字段：厂商、题号、轮次、得分（0/1/2）、错误类型标签（幻觉/推理断裂/格式违规/拒答不当/指令未遵循）、备注。

加权口径按“四、测评方法学 → 2.各项占比”执行：综合能力 60%（A–D/G/H 类）、异常识别 10%、指纹一致性 20%、稳定性 5%、Token 消耗 5%。

输出物：每题得分明细表 + 按维度加权总分 + 跨厂商差异结论（差异 ≤5% 正常；5–15% 有差距；＞15% 明显弱）。

## 4. 完整测评执行顺序

1. 采集：同一题同时请求云厂 A/B/C，记录输出、token 与耗时，每题重复 3–5 次。
2. 脱敏：去掉回答中的模型名与厂商名。
3. 判分：客观题脚本比对；开放式题按提示词模板 LLM 盲评。
4. 汇总：按登记表字段记录，计算加权总分与差异。
5. 输出：结论 + 明细表 + 风险提示（模型不一致/掺水/不稳定）。

## 6.人工复核规范

 不做全量人工打分，仅做质量校验，禁止直接修改单条样本分数 

#### **1. 抽样两部分：**

1. **随机抽10–20%（含0/1/2分）**
2. **score=0 全部复核**
3. **人工只判断：评分对/错（不改分）** ① 随机抽取全部样本的10-20%（包含score=1与score=0）  ◦② 全部bad‑case（score=0）必须全部人工复核  

#### **2.** 一致率判定（核心结论）

- **≥90% → ✅可信（可以用）**
- **80–89% → ⚠️预警（优化后重跑）**
- **＜80% → ❌作废（必须重跑）**

#### 3、异常处理

🟢 **少量误判（<10%）**

- 记录台账
- 修规则/白名单
- **本轮不改分 ✅**

---

🟡 **中等异常（80–89%）**

- 问题在评分（prompt / rubric）
- 修评分逻辑
- **只重跑评分（不用重新调模型）**

---

🔴 **系统性错误（＜80%）**

- 修：GT / 脚本 / 判分逻辑
- 数据集版本 +1
- **全部重跑（调用+评分）**
- **旧结果作废 ❌**
