# 海外大模型接入测试与质量治理方案

> 公开整理版。接入后和长期治理部分仍为待优化草案。下文告警阈值仅供筛查；指纹差异不能单独证明模型被替换，计数差异不能单独证明计费造假。
> 统一说明见 [已知限制与整理记录](limitations.md)。

# 🎯 方案核心结论
**本方案解决三大核心风险：**
1. **模型风险**：防止模型被降级/替换（GPT→低版本/开源模型）
2. **计费风险**：防止Token虚增、重复计费
3. **算力风险**：防止延迟异常、限流、动态降配
**测试框架三阶段：**
- **接入前**：多云厂对比 + 指纹测试 + Token计费验证 + LLMmap识别
- **（待优化）接入后0-3月**：高频抽测 + Token监控 + 身份识别
- **（待优化）长期运行**：A/B测试 + 趋势监控 + 定期识别
**关键指标阈值：**
- 模型降级：评分下降>15% → P0报警
- 模型替换：LLMmap相似度<80% → P0报警
- Token掺水：用量上升>20% → P1报警
- 算力异常：延迟上升>30% → P1报警

# 一、项目背景与核心问题

在企业接入海外大模型过程中，由于无法直接调用官方API，仅通过云厂商中转，存在**三类核心风险**：


### 🔴 风险1：模型风险
- 模型被降级（如 GPT → 低版本）
- 模型被替换（如 GPT → 开源模型）
### 🔴 风险2：计费风险
- Token虚增（掺水）
- 重复计费或异常计费逻辑
### 🔴 风险3：算力与服务风险
- 延迟异常（算力不足）
- 并发受限（限流）
- 高峰期动态降配

### 3.2.2 概率指纹测试（模型一致性，建构基线，便于后续测试有没有换模型）

[论文方法的Github网址](https://github.com/hifi-hyp/ACL-LLMPrint)

#### 基线构建方法

- 每模型执行3轮独立测试
- 每轮50题，每题10次采样
- 对结果取均值作为概率指纹
- 同时计算标准差作为稳定性指标
- 剔除高波动题，形成最终基线向量

#### 测试内容

- 二选一指纹题（50道）
- 多次采样（10–20次/题）

#### 输出指标

- 概率指纹向量
- 指纹一致性（与基线对比）

[概率指纹测试题库](probability-fingerprint.md)

## 4.3. 异常检测与判定规则


**核心报警阈值一览**：
- 🔴 **模型降级**：评分下降>15% → P0
- 🔴 **模型替换**：LLMmap相似度<80% → P0
- 🟡 **Token掺水**：用量上升>20% → P1
- 🟡 **算力异常**：延迟上升>30% → P1


###  🔴 严重异常（红色）

满足任一条件即触发：

- 总评分下降超过15%
- 一致性评分低于60%
- LLMmap识别结果Top1模型发生变化
- 安全策略评分低于8分

**处理措施**：

- 立即报警
- 启动人工复核
- 视情况暂停模型调用

---

### 🟡 预警（黄色）

满足任一条件：

- 总评分下降5%–15%
- 模型相似度下降超过10%
- Token使用出现异常波动

**处理措施**：

- 标记风险
- 持续观察与复测

---

### 🟢 正常（绿色）

- 总体波动在5%以内
- 指纹识别稳定
- 各项评分正常

---

## 4.4、输出结果（标准化）

每日输出统一检测结果，包括：

- 总评分及各子评分
- 模型指纹识别结果（Top1及相似度）
- 异常状态（正常 / 预警 / 异常）
- Token使用情况

# 五、3月后长期抽测与优化机制


**目标**：建立长期可持续的监控与优化机制，确保模型质量、成本、身份的持续稳定


---

## 5.1 指纹题库-抽测频率

| 频率 | 规模 | 含义 |
|-|-|-|
| 每月 | 小规模 | 抽样跑少量题，做快速体检，及时发现明显漂移 |
| 每季度 | 全量 | 跑完整指纹题库 + 全维度验证，做全面体检 |


**为什么要分两档**：
1. 全量测试成本高、耗时长，不能天天做
2. 但只做每月全量又太慢，被掉包可能要一个月才发现
所以用"高频小规模 + 低频全量"组合——**小规模负责快速报警，全量负责精确定位和留证据**


---

## 5.2 模型身份周期验证

每月固定执行：

- **LLMmap 识别**：重跑模型身份指纹，看云厂给的还是不是标称那个模型
- **与历史基线对比**：不只是"像不像 GPT/Claude"，更要看"跟它自己上个月比，有没有变"


**关键点**：模型替换不一定是换成 GPT→开源这种大变化，也可能是同厂悄悄换个小版本。跟历史基线对比，能抓到这种"缓慢漂移"，比单次比对基线库更灵敏。这是对 4.3 节中的相似度报警的定期兜底检查。
