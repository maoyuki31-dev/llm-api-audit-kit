## 结论的边界

- 模型自报名称、输出风格或与首次接入结果相似，均不能独立证明模型身份。参考库覆盖、系统提示、参数、量化、模型更新和网关路由都可能影响观测。
- Temperature 为 0 不能保证服务端完全确定性；缓存、随机种子、系统提示和版本是否可控必须如实记录。BF16 / INT8 等配置在托管 API 中可能不可观察或不可控制。
- 评分下降 15%、相似度 80%、Token 增长 20%、延迟增长 30%、复核一致率 90% 等为原方案的建议阈值，没有随本版提供校准样本、误报率或验收验证。
- 原文“安全策略评分低于 8 分”未给出统一量表；归一化、权重和缺失值处理必须先定义。文献准确率属于对应实验条件，不能当作本项目保证。
- 95% 区间重叠与否不能替代正式差异检验。重复使用同一题库时需考虑配对样本和多重比较；原脚本的区间算法需要修订。
- 题库中的价格、功耗、发布时间或虚构名称属于题目设定，不能当作采购行情或事实来源。B7 的“最优”缺少明确目标；E3、G4、G5、H3 等仍需上下文；G1 应明确单位成本算力比的单位，G7 应明确第二问的可用性口径。
- 本次没有对原始脚本开展功能测试、真实 API 调用、完整研究复现或供应商验收。脚本的已知问题见 [参考代码说明](../examples/README.md)。
